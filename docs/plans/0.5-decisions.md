# Skill Gate 0.5 — product decisions (plan)

> **Phase 1 is this plan.** Phase 2 implements it on `cursor/0-5-decisions-3b9f`. Do **not** merge. Do **not** bump/publish PyPI from this PR beyond the in-tree version string. Do **not** flip the repo public.

**Goal:** After 0.4.2 E2E QA, Skill Gate is live-only: every check is a real model run with keys the user set in Skill Gate, examples ship in the wheel, deploy is skill-files-only after a check, and the CLI grows `init` / `new` / `example` / `keys`.

**Parents:** PR #13 (`cursor/react-ui-local-mode-3b9f`, React UI + live llm-harness bugs) and `main` @ `4c008bc` (0.4.2 engine/CLI/docs QA, #16). This branch starts at #13 HEAD and merges `origin/main`.

**E2E source:** Vignesh’s 0.4.2 live QA (report summarized in the 0.5 request; file was not on this box).

**Version:** in-tree **0.5.0** (`pyproject.toml`, `skillgate_ai.__version__`). Breaking vs 0.4.x.

## 0. Locked product decisions

These are not open questions. If a later change fights one of these, the lock wins.

### 0.1 Live-only (A)

- Remove the **demo harness** as a product path. No `--demo`. No “built-in checker”. No “not a live model”.
- `skillgate check` always picks a live harness (Cursor / Codex / Claude / OpenAI-compatible), same as UI **Run**.
- Deterministic **scorers** (file exists, contains, page count, skill trigger) stay. They score the live run’s artifacts. They are not a substitute harness.
- OpenAI **judge** still runs when an OpenAI or gateway key is in the Skill Gate store. Without those, det scorers own pass/fail. Copy must not say “built-in checker”.
- `--live` is implied; drop the flag (or keep it as a no-op alias for one release — prefer drop).
- `--expect-fail` stays (CI for a skill that should fail).

### 0.2 Keys are explicit (B)

Provider keys are **never** read from ambient process env (`OPENAI_API_KEY`, `AI_GATEWAY_API_KEY`, `CURSOR_API_KEY`, `CODEX_API_KEY`, `ANTHROPIC_API_KEY`) and **never** from a project `.env` under those names unless the user opted in.

| Source | Used? |
| --- | --- |
| `{project}/.skillgate/keys` (0600), written by Settings and `skillgate keys set` | **Yes** |
| `SKILLGATE_OPENAI_API_KEY`, `SKILLGATE_AI_GATEWAY_API_KEY`, `SKILLGATE_CURSOR_API_KEY`, `SKILLGATE_CODEX_API_KEY`, `SKILLGATE_ANTHROPIC_API_KEY` | **Yes** (CI / Action) |
| `--key-env OPENAI_API_KEY` (repeatable) | **Yes** — bind that process env name for this process |
| Ambient `OPENAI_API_KEY` with no prefix and no `--key-env` | **No** |
| Project `.env` `OPENAI_API_KEY=...` | **No** (Settings no longer writes `.env`) |

Non-secret Skill Gate config (`SKILLGATE_MODEL`, `SKILLGATE_HARNESS`, `SKILLGATE_ROOT`, …) may still come from env / dotenv.

No key → **Run disabled** in the UI; CLI `check` / `run` **exit 2** with: add a key in Settings (`skillgate ui`) or `skillgate keys set`. Do not start a harness.

`.skillgate/` is already gitignored.

### 0.3 Deploy (C, E)

- **Never auto-check** on deploy/install/sync.
- Refuse if this skill has **no passing check** in pack history (never checked, or latest relevant run is not a pass). Plain: “Run the checks first (`skillgate check` or press Run), then install.”
- 0.4.2 already refuses a **red** latest check; 0.5 also refuses **missing** history. No `--force` on the default path (0.4.2 `--force` stays as an explicit override if it already exists; do not advertise it in README).
- Copy **only the skill**: `SKILL.md`, `scripts/`, `references/`, `assets/`, and other non-eval files. **Exclude** `evals/` (fixtures, goldens, cases, history) and any history JSONL.

### 0.4 Examples in the wheel (D)

- Package `skills/pdf` and `skills/pdf-sabotaged` as `skillgate_ai/examples/{pdf,pdf-sabotaged}` (build copies from repo `skills/`, like `web_static`).
- `skillgate example pdf` / `skillgate example pdf-sabotaged` writes a copy into cwd (or `--dest`).
- README quickstart after `pip install skillgate-ai`: `keys set` → `example pdf` → `check pdf` (needs a live key). Do not promise a keyless green check.

### 0.5 CLI create flow (F)

Match the UI create-skill path (`create_pack` + `scaffold_trigger_cases`):

- `skillgate init [dir]` — make a workspace (`skills/`, ignore keys). Idempotent if already a workspace.
- `skillgate new NAME` — `skills/NAME` with SKILL.md + trigger cases. Default parent is `skills/` under the project root.

### 0.6 QA bug locks

| Bug | Lock |
| --- | --- |
| Quoted RUN argv | Keep #13 `shlex.split` in `_parse_run_lines`; skill-scripts-only allowlist; no `shell=True`. |
| Wrong FAIL advice | Keep #13 command-failed copy. Remove leftover “pdf twin” / “Corrected SKILL.md description” from CLI/UI. |
| Duplicate error printing | One human message per failure (CLI must not print `exc.render()` and the same `CheckResult.error`). |
| `skill:` mismatch in `evals/cases.yaml` | If `skill:` is not this folder’s name, **SuiteError** in plain words (“This check file is for `{yaml}`, but the folder is `{folder}`.”). |
| Local UI CSRF / paths | POST/PUT/DELETE require `Content-Type: application/json` (or multipart for uploads). Reject cross-site and `text/plain`. Require `Origin` or `Host` to be `127.0.0.1` / `localhost` / `::1` (with port). Validate `Host`. Resolve all pack paths under the workspace root. |
| `ui --port 99999` | Port must be 1–65535; out of range → exit 2, “Port must be between 1 and 65535.” |
| `--target` / `--targets` | Same option on deploy and sync: `--target` and `--targets` both accept one name or a comma list. |

### 0.7 CI / Docker without secrets

Live check cannot run in this repo’s GHA without keys. **Do not** keep `skillgate check skills/pdf` as a keyless green job.

- `gate` job: `skillgate example pdf` + `ingest`; optionally `check` only if a `SKILLGATE_*` key secret is present.
- Docker image job: build + `example`/`ingest` against a copied pack; do not expect exit 0 from keyless `check`.
- Document Action: `skillgate check . --key-env OPENAI_API_KEY` with `env: OPENAI_API_KEY: ${{ secrets.OPENAI_API_KEY }}` (or `SKILLGATE_OPENAI_API_KEY`).

### 0.8 Judge / Gateway (from #13, unchanged)

OpenAI key → `POST https://api.openai.com/v1/decisions`, `gpt-6-luna`. Gateway-only key in the Skill Gate store → same Decisions API on the gateway (`openai/gpt-6-luna-decisions`). Never reroute an OpenAI key through the gateway. Never score via `/responses` as the default.

## 2. Files to change (Phase 2)

### 2.1 Keys

- **Create** `src/skillgate_ai/keys.py` — load/save `{root}/.skillgate/keys` (KEY=value, 0600), `SKILLGATE_*` overlay, `--key-env` bindings. Never log values.
- `config.py` — `get_llm_config()` reads keys module, not ambient provider names. Keep dotenv for non-key `SKILLGATE_*`.
- `api.py` Settings PUT/DELETE → keys file, not `.env`. `keys_payload`: `from_vault` = keys file; `from_env` = only `SKILLGATE_*` or `--key-env` (not ambient).
- `cli.py` — `keys` typer group: `set`, `clear`, `list` (names only).
- Tests: `tests/test_keys.py` — ambient `OPENAI_API_KEY` ignored; store + prefix + `--key-env` work.

### 2.2 Live-only engine

- `gate.py` — drop `DemoHarness` fallback and `DEMO_NOTICE`. No key → `CheckResult` error exit 2.
- `harness.py` — stop resolving `demo` from auto. Keep `DemoHarness` deleted or unused (prefer delete if tests can move).
- `cli.py` — remove `--demo` / `--live`; add `--key-env`.
- `api.py` / `api_runs.py` — Run without key → 409, Settings hint, no start.
- Web: `eval-page.tsx`, `skill-run-state.ts`, `check-results.ts` — disable Run; delete “built-in checker” / “not a live model”.
- `report.py` — no “Corrected SKILL.md description”; no “built-in checker scored”.
- `advice.py` — no “pdf twin”.
- Docs: README, quickstart, pack.md, ui.md, openai-judge.md, AGENTS.md.

Tests that today assert demo/green without keys **must change** to assert the no-key error (do not keep a hidden demo path to make them pass).

### 2.3 Deploy + examples + scaffold CLI

- `pack.copy_skill_pack` / deploy adapters — skip `evals/` (and history).
- `deploy.py` / `cli.deploy` — history has a passing check; no `run_check` inside deploy.
- `skillgate_build.py` + `package-data` — copy `skills/pdf` and `skills/pdf-sabotaged` into `skillgate_ai/examples/`.
- `cli example` / `cli init` / `cli new`.
- `suite.py` / `case_pack.py` — `skill:` must match folder name.

### 2.4 Local UI security + UX

- Middleware on `create_app`: Host allowlist; mutating methods need JSON (or multipart) and matching Origin/Host; `text/plain` POST 403.
- Path helpers already exist (`is_relative`); apply on every skill/pack path.
- `ui_cmd` — validate port 1–65535 before uvicorn.
- Deploy/sync — `--target` and `--targets` both accepted.

### 2.5 CI

- `.github/workflows/gate.yml` — no keyless `skillgate check` green; example + ingest; Docker job aligned.

## 3. Test plan (TDD)

Write failing tests first; never weaken.

1. **Keys** — ambient ignored; store / `SKILLGATE_OPENAI_API_KEY` / `--key-env`; list never prints secrets.
2. **No key** — `run_check` exit 2; UI status `has_key=false` disables Run; CLI message names Settings and `skillgate keys set`.
3. **Live-only** — no `DemoHarness` in auto; no `--demo` in `--help`; customer strings deny-list: `built-in checker`, `not a live model`, `pdf twin`, `Corrected SKILL.md description`.
4. **Deploy** — never-checked refuses; passing history allows; dest has no `evals/`; `--force` behavior only if kept from 0.4.2.
5. **example / init / new** — wheel contains examples; `example pdf` writes SKILL.md; `new` matches scaffold.
6. **cases.yaml** — `skill: other` in folder `pdf` → SuiteError, no traceback.
7. **Quoted RUN** — keep `tests/test_harness_llm.py`.
8. **Security** — TestClient POST without JSON / with evil Origin → 403; path `../` → 404/400.
9. **Port / targets** — `--port 99999` exit 2; deploy `--targets cursor,codex` works.
10. Full: `GITHUB_ACTIONS=true FORCE_COLOR=1 python3 -m pytest -q`; `pnpm --dir web test`; `pnpm --dir web build`.

## 4. Risks

- **Many tests** assume keyless demo green (`test_check_cli`, `test_gate`, `test_local_ui`, GHA `gate` job). They change to the new contract.
- **Merge `origin/main` (0.4.2) into #13** will conflict in `cli.py`, `gate.py`, `harness.py`, `advice.py`, `pack.py`, `deploy.py`. Resolve by keeping 0.4.2 QA behavior except where 0.5 locks override (no auto-check, no demo, keys store).
- **Docker `CMD check /pack`** without a mounted keys file will exit 2. Document it.
- **`.env` users** from 0.4.x must re-enter keys in Settings. README one-liner.
